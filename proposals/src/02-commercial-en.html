2 Ways of working and communication

2.1 The cadence

Iterative delivery in two-week cycles. At the end of every cycle we deliver a build you can actually try on the staging environment — not a report of percentage complete. That means you watch the product grow and can correct course early, rather than waiting for final delivery.

The project owner — you lead the product
You approve the design, set priorities, answer business questions, provide third-party provider accounts, and carry out acceptance testing. Your decisions determine what enters scope and what is deferred.
RoboAgentix — we build and deliver
We design, develop, test, deploy, document and train, and we guarantee that every cycle ends in a stable build you can try, and that every technical decision is explained and recorded.

2.3 Quality gates inside each cycle

#GateEffect
1Mandatory code review No code is merged without another developer's review — this prevents technical debt accumulating and spreads knowledge across the team.
2Automated tests on every build Unit and integration tests run on every push, and a failing test blocks the merge.

4 How the work is delivered

The project is delivered by a small, focused team working on an AI-assisted engineering toolchain. This is not an organisational footnote — it is the reason for the price and the timeline in this proposal.

A small team, single ownership
No management layers and no handoffs between teams. Whoever designs the system is who builds and delivers it, so knowledge is not lost between stages and you do not pay for internal coordination.
AI tooling in the production path
Code generation and review, test construction and documentation generation are accelerated by tools we use daily. Hours shrink without quality shrinking, because every output passes human review and automated testing.
Proven, ready components
Authentication, payments, notifications, uploads and permissions are patterns we have built before and do not rebuild from scratch. Effort concentrates on what makes AWNAK distinctive: the dispatch engine, the financial layer, and the flexible service catalogue.

Guaranteed continuity The code is documented, tested and handed over in full, and any other team can pick it up later — so there is no lock-in to us.

10 Warranty and technical support

10.1 The included warranty period

One hundred and eighty days from the date of publication on both stores. During that period software defects are fixed at no charge — a defect being any behaviour that departs from the technical document and the approved requirements analysis.

SeverityDefinition Response timeResolution time
CriticalBlocks the order cycle, halts the system, or affects the integrity of funds. 4 working hours24 hours
HighDisables a major function while a temporary workaround exists. 1 working day3 working days
NormalLimited-impact defect or a cosmetic issue. 3 working days10 working days

Faults are received by dedicated email and the shared communication channel, with a numbered ticket per report tracked through to closure.

10.2 What the warranty does not cover

  • New changes and additional functionality — priced through change control.
  • Changes caused by payment, maps or app store provider updates, or operating system updates — estimated separately.
  • Faults arising from code or configuration changes made by another party after handover.
  • Outage of an external provider, or exceeding that provider's account limits.
  • Incorrect data entry or misuse of the admin panel.

11 Change control

Change is normal on a project of this size. What matters is that it is never ambiguous — every change request follows a published path with a price known before it is carried out.

1
A written request
The project owner sends the change request through the agreed channel, described in enough detail to assess its impact.
2
An estimate within three working days
We respond with an estimate of hours, cost and schedule impact, with no commitment on your part.
3
Approval or rejection
No change is carried out before written approval. Rejection carries no cost.
4
Delivery and documentation

12 Ownership, rights and confidentiality

An explicit undertaking Ownership of the application, the systems and everything produced within this project rests entirely and without reservation with the project owner, effective on settlement of the final payment.
  • The complete source code is handed over — server, app, admin panel, marketing website, database migration files and version history.
  • App store accounts are created and remain in the project owner's name.
  • Hosting, domain and external service accounts are created in the project owner's name and all access credentials are handed over in full.
  • RoboAgentix may not resell the same system with the project's data, identity or content.
  • Customer and provider data may not be used for any other purpose, under any circumstances.
  • Complete confidentiality over project information during delivery and afterwards, without time limit.
  • RoboAgentix may cite the project as a reference only with prior written consent.

RoboAgentix retains ownership of its own general-purpose internal tools and libraries that are not specific to this project, and grants the project owner a perpetual, irrevocable licence to use them within this system at no further cost — so no future obligation or dependency arises from them.
